# BV 极致性能优化状态

## 目标与清理说明

根据用户的需求，本次优化的核心目标是在 **Android TV 端提供最高画质与极限流畅度的播放体验**（特别是 4K/Dolby）。该版本旨在为高配电视或盒子打造专属的极致性能体验，无视部分低端设备的兼容限制。

我们没有采用创建大量冗余日志文件的方式，以避免无端占用空间并保持代码整洁。取而代之，我们优化了播放器的悬浮提示界面 `PlayStateTips`，当视频处于暂停状态时，会在右下角的暂停图标旁展示一个 **状态二维码**。用户只需要扫码即可实时获取当前优化的开关状态。

## 已实现功能拆解

以下功能均可在应用设置 -> 极致优化菜单中开启或关闭：

### 1. 智能最高画质自动索取
- **描述**：起播时忽略系统默认画质偏好，每次都自动解析会员账号支持的最高画质（天花板画质）。
- **实现机制**：修改 `VideoPlayerV3ViewModel` 内的 `calculateTargetQuality` 逻辑，并在 `updateMediaProfile` 以及 `PictureMenu` 层面拦截 UI 的手动画质变更，弹出提示避免误操作降级画质。

### 2. 起播前内存感知智能 GC 防卡顿
- **描述**：通过在视频解析与起播之间进行毫秒级的内存状态探测，避免播放过程中由于高画质缓存瞬间占满内存而导致 JVM 被动引发 Stop-The-World 的严重卡顿。
- **实现机制**：在 `VideoPlayerV3ViewModel.initVideoPlayer` 初始化前探查空闲内存。如果内存占用大于 70% 或空闲内存低于 200MB，主动执行 `System.gc()` 并添加 30 秒的节流（Throttle）防频繁调用，该时机选择在黑屏转场的空隙，对用户感知影响最小。

### 3. ExoPlayer 内核调优与 Tunneling
- **描述**：将 ExoPlayer 底层的各项设置拉满，以追求最极限的高画质吞吐量。
- **实现机制**：在 `ExoMediaPlayer` 的初始化过程中传递并激活三项核心配置：
  1. 开启 **DynamicLoadControl**，将最大 Buffer 时长增加至 120 秒，提供充足的缓冲池。
  2. 启用 **Tunneling 隧道直通**，绕过 SurfaceFlinger 的合成，减少掉帧率，极大增强大码率（4K HDR/Dolby）播放流畅度。
  3. 配置高优先级 MediaCodec 并行解析队列选项。

### 4. 进度条缩略图降级采样 (OOM 防护)
- **描述**：在使用进度条快速 Seek 时，缩略图加载极易撑爆高画质视频预留的珍贵内存。
- **实现机制**：在 `VideoShotExtends` 的 BitmapFactory 配置中强制注入 `inSampleSize = 2`，以极低的成本将精灵图（Sprite Sheet）解码的占用内存缩小为原本的四分之一。

## 观察与测试建议

编译并推流后，您可以进入播放器暂停视频，用手机扫描右下角的二维码查看各项调优参数是否正常启用，并在播放不同码率的视频时感受响应速度和画质。
